# 网站策划与设计

把本次产品、实际参考和可用素材转成能实现的设计。用户只给产品名即可开始；自行研究访客任务并标记假设，不把买家画像、完整文案、图片和参考清单作为开工前提。确实不知道做什么业务时才问最小缺项。仅讨论方案时不创建网站。

## 执行

1. 已有项目先读实际工程、版本、交接和用户明确保留项，保护内容与数据。新建则研究当前产品、采购或使用路径，确定内容职责；专业事实查原始可靠资料。企业资质、价格、产能、案例和联系方式缺失时记录缺项，不编造。产品不同，重新决定页面、顺序、构图和交互。
2. 有 Refero Design 时沿用它的研究、主要方向选择和对照方法；本 Skill 负责产品策划、资源选择和交接，不另立竞争设计规则。按 [资源接入](references/resources.md) 调用本地检索；采用项回读原文、实际查看相关页面。资源和实时检索不可用时记录原因，使用可访问实际来源继续，不反复重试同一失败。检索目录、源码、截图、真实操作分别登记。
3. 决定导航、各页面与模块解决的问题、内容顺序理由、图片作用与裁切、排版层次、操作反馈和响应布局。主方向保持一致；其他参考只补明确缺口。商店参考不自动增加购物车或支付。素材不足时选择能成立的构图，按需调用图像工具制作实际资产；概念图不充当真实产品、工厂或客户证据。
4. 从当前关键用户路径选最小而完整的样板范围，可以是一页多个状态，也可以跨页。使用真实可得内容，主动覆盖最难的标题、图片、参数或操作；不固定首页/详情/询盘三页。四个问题“谁做什么、内容为何这样排、怎样表达及依据、素材技术是否可行”足以支持样板后开始实现，不为凑数量继续研究。
5. 按 [交接协议](references/handoff.md) 写入建站已有的项目文档，交给实际建站执行者。一般设计决定自主完成；缺口不阻碍样板就继续。完成计划不代表页面完成，初版完成不代表审美通过。

## 交接与修订

使用 unified-site-builder 时读取实际版本的设计、模块接线与主题接口；现有业务核心由建站 Skill 负责。规划中的字段要对应后台管理位置。选中实验室组件时登记独立入口、依赖、内容输入、事件、销毁和回退；只引入所选实现。不要导入实验室总目录、演示主题或第二套询盘数据库。

询盘适配器统一由建站 Skill 维护，使用生成工程的 `/assets/inquiry-adapter.js`，本包不再复制业务实现。交接前按 [兼容性检查](references/compatibility.md) 检查已安装建站版本与工程接口；旧工程须先比较原核心，再按原项目更新流程适配，不能只改版本号。

设计偏差由实现修正；真实素材或技术限制影响设计时，修改相关决定并记录原因，不能悄悄换成默认主题。后续使用 website-quality-review 对照实际页面核对。两个 Skill 可以由同一执行者顺序使用，不自动生成独立代理或后台调度。

## 工具与边界

`python scripts/resources.py doctor` 检查已配置目录；`search --query "关键词" --kind all` 只返回候选；`inspect --id <ID>` 回读原文或接入说明。配置只存用户环境，不随公开包发布。工具不会联网、作审美选择或操作页面；候选分数不代表质量排名。未配置库仍可研究公开来源并完成策划。

联动入口与失败回退见 [两 Skill 配合](references/workflow.md)。来源、工具实际调用和证据随项目记录，单一执行者如实登记。默认沿用用户现有部署约定；本 Skill 不自行购买、部署或改变已有项目。
