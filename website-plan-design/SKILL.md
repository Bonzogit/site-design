# 网站策划与设计

把简短的产品或业务需求转成建站执行者能够直接实现的方案。主动完成研究与一般设计决定，不要求用户先交买家画像、完整文案、图库或参考清单。用户只要方案时交付方案；要求建站时把同一方案交给建站 Skill 继续执行。

通用于产品展示、服务获客、品牌内容、交易和工具等网站。网站类型由当前任务决定，不默认外贸询盘站；实际功能由需求和建站能力共同决定。具体项目名称、旧网站布局和过往验收结果不作为新任务默认值。

## 从需求推导方案

1. **确定网站要帮助谁完成什么。** 先识别访客进入时已知什么、要判断什么、行动前担心什么，以及网站期望的主要结果。只有名称时，根据公开资料推导合理的主要访客与用途，标明假设后继续；仅在业务类别都无法判断或目标相互冲突时提问。已有网站先读取当前任务、内容、业务能力和保留项。
2. **从决策障碍安排信息。** 产品研究提取的是选型维度、证据需求、典型疑问和内容差异，不是堆行业常识。按访客需要回答的问题确定页面、导航和阅读顺序；每个模块都要说明“回答什么、依据是什么、为何放这里、下一步是什么”。详读[策划与内容](references/planning.md)，把结论落实到页面蓝图，不能停在“突出优势、提高转化”。
3. **观察参考并做出一套设计选择。** 参考分别解决结构、视觉或交互问题，拟采用的页面需实际观察；来源与观察方式登记。可用时沿用 Refero 的研究方法，资源选择按[资源接入](references/resources.md)，平台不可用仍可使用实际可访问来源。依据产品、内容和素材选一个主方向，明确采用点与舍弃点。按[视觉与交互](references/design.md)落实构图、字体、颜色、密度、图片、组件、状态和响应方式。
4. **把素材与内容变成实施输入。** 输出主要标题、行动文案及关键说明的可用草稿，企业事实与推定分开。图片要指定主体、用途、构图、比例、裁切和来源；需要生成时给出制作要求，不能把概念图当实物证据。长标题、多规格、内容为空、加载失败等困难状态要在方案中有处理方式。缺少非关键资料时选能成立的表达继续，不编造客户、认证、销量、价格或联系方式。
5. **形成可直接建造的交接。** 给出页面蓝图、具体视觉参数、素材清单、关键路径和可观察的验收预期。选取能验证最大设计风险的最小完整样板，可为一页多个状态或跨页；不固定页面数量与模块组合。已有文件就回写同一份方案，按[交接协议](references/handoff.md)连接字段、后台与实现，不让建站执行者重新猜设计。

## 完成条件

交接应足以回答：每页做什么；每块写什么、长什么样、用什么图；访客怎样操作；窄屏与失败状态怎样呈现；内容怎样维护；实际检查什么结果。字体、间距、宽度和裁切给出本次具体选择，不能只写“高级、简洁、响应式”。

方向、关键内容和技术依赖足以开始样板后就交接；不为凑参考或文档数量继续研究。实现约束影响方案时修订相应决定；验收发现产品逻辑问题返回策划，布局与接线偏差交由建站修复。完整联动见[工作流](references/workflow.md)。

## 与建站 Skill 配合

策划负责网站任务、内容与设计决定；建站负责工程、业务核心、内容保存与部署；验收 Skill 负责对照预期观察实际结果。沿用已有工程和数据，不把参考站或组件库的演示后端带入客户网站。

只有使用 unified-site-builder 时，才读[该建站器的适配规则](references/compatibility.md)并运行对应检查。其他建站器先读取其实际内容、主题和业务接口再映射，不强塞统一建站的文件名与 API。可选资源脚本只帮助发现和回读候选，不能代替设计决定；没有本地资源库仍可完成工作。
