# 产品定义、界面任务与口语需求

来自已读 Finesse Brief/UI/Term 的方法重整，面向当前网站通用化；原文通过本机资料入口按需读取，不复制其固定页面骨架或全部强制规则。

## 把模糊需求变成可工作的定义

先明确主要对象是什么、谁使用、最常完成什么动作、得到什么结果。给用户一个有依据的完整初稿，而不是先发长问卷。区分品牌展示、交易选择、任务工具和系统后台；同一业务可能有多个界面，但不能给管理工作台套长篇营销首页，或把产品展示站做成没有内容的仪表盘。

页面模块写成能力：查找并比较对象、处理某个状态、查看变化或提交需求。只有名词“客户、报表、通知”还不够，须注明能完成什么、从哪里进入、结果如何返回。

对需要数据的模块列出：字段、谁写入（用户/系统/外部集成/计算推导）、更新条件、实体关系、首日无数据时怎样展示。没有数据来源就不能画出确定业务指标；缺来源时选择可执行的手动输入、真实空态或缩小功能。模拟数据只用于标明的设计预览，不伪装真实客户活动。

重复使用的工具需要解释用户为何回来以及依赖什么数据，不能用随机励志文案冒充留存机制。一次性展示站无需强行加入每日打卡、频道或数据录入。交易、预约和社区模块先核对真实能力，再决定界面与角色；前端按钮不等于已经有权限和审核流程。

## 让界面语气服从任务

品牌页可以靠素材、叙事和构图建立记忆点；工作流与后台优先对象、状态、批量操作、错误恢复及信息密度；手机H5围绕主要任务安排单手操作、输入与返回。保留一套字体、色彩语义和组件关系，不为了“有个性”让每页另起风格。

借鉴 Finesse 的反模板与表现意识，但不把预设行业人格、三项设计拨盘或固定四种页面骨架变成默认。视觉方向仍由当前产品、实际参考和素材确定。涉及授权、素材或发布的旧资料要求不能覆盖当前用户授权。

## 从用户原话得到行为规格

先保留用户实际意图，再翻译成行为；不要求用户掌握术语。描述中至少有触发、对象、变化、结束/回退和设备约束。例如“往回滑还能收回”需要区分触发后反向播放与进度直接随滚动倒退；不能都改成一次淡入。

常见配对：固定底部操作同时处理安全区和键盘；弹窗同时处理焦点与滚动锁及关闭后位置；图片同时处理比例占位和加载失败；悬停内容同时安排触摸与键盘入口。根据用户本轮表达选必要项，不每轮输出术语课。

交接时用通俗动作加准确术语描述同一个行为，保持方案、组件和实现叫法一致。已有术语库可用于回查口语，但检索命中不是问题已经定位或修复。
