# 策划与页面内容

## 先找到访客的判断顺序

把主要路径写成“进入时的问题 → 需要比较或确认的内容 → 降低顾虑的证据 → 合理行动”。入口可能是搜索详情页、分享文章或广告落地页，不默认所有人先看首页。主要访客不确定时选一个有依据的主假设，同时注明改变假设会影响哪些决定，不编造完整买家画像。

| 主要任务 | 优先组织的信息 | 合理页面组织依据 |
|---|---|---|
| 判断产品是否适用、比较差别 | 适用场景、差异维度、规格、真实图片、兼容与限制 | 需要并排判断时用对比；型号多才需要分类/筛选；详情突出影响选择的参数 |
| 选择服务并建立信任 | 解决的问题、交付内容、合作过程、责任边界、可核实证据 | 按顾虑与合作阶段展开；范围与流程常比堆服务卡片更有用 |
| 购买或预约 | 选项、价格条件、库存/时段、履约、售后、交易状态 | 先核对真实交易能力，再安排选购和确认；不能用询盘按钮假装支付 |
| 使用工具完成工作 | 输入要求、主要操作、结果、状态保存、错误恢复 | 让任务界面优先，不强塞长篇品牌首页；首次使用说明靠近实际输入 |
| 阅读、探索或理解品牌 | 内容价值、主题组织、作品或叙事、阅读路径 | 由内容节奏决定版式；只有实际内容支持时才采用长叙事与大图 |

这些是判断线索，不是互斥模板。一个网站可以有多种任务，但每页要明确主要任务，避免所有按钮同等抢眼。

## 研究只填补影响决策的缺口

产品资料用于确认真实属性与术语；同类网站用于观察访客怎样寻找信息、比较和行动；跨行业参考用于解决具体的呈现问题。引用到页面和观察内容，不凭项目名、仓库 stars 或模板简介决定采用。

记录四类信息：已核实事实、用户提供事实、工作假设、待补事实。假设可以支持布局推演，不能写成企业宣传。没有资质或案例就改用可验证的产品说明与合作条件，不用空白 Logo 墙和虚构评价填版面。

缺图时先判断是否阻碍理解：需要看结构、材质或结果的内容应补图；抽象服务可以靠清晰的说明和流程成立。缺型号或真实报价时，不编产品目录和价格表。文案不确定时写可修改的草稿，并说明事实依赖，不让整个方案停在占位标题。

## 页面蓝图

每页用一行说明“入口、主要任务、完成条件”，随后逐模块列出：

| 字段 | 交给实现者的信息 |
|---|---|
| 模块目的与顺序 | 解决哪个问题，依赖前面什么信息，为何在这里出现 |
| 内容 | 标题与关键说明草稿、实际数据、字段、事实来源与缺项 |
| 呈现 | 主次关系、布局方式、内容长度、图片或图表位置及作用 |
| 操作 | 点击/滚动/选择后的结果、跳转目标、必要的空态与失败反馈 |
| 手机表达 | 哪些内容重排、折叠、换图或保持；不能只写“自适应” |
| 维护与检查 | 内容由哪里编辑、由哪个接口读取；验收时用户能看到什么结果 |

全站导航按访客寻找内容的路径命名，不按公司部门或通用模板栏目凑数量。首页负责引导，详情负责完成判断，不强迫每页重复全部卖点。只有长度、内容数量或用户任务有依据时才增加页面。

## 文案与行动

首屏要让访客读出“是什么、适合什么、下一步能做什么”，具体句式取决于产品和入口。标题表达可核实的对象与价值，副文案补条件与差异；行动按钮说明会发生的事。少用“探索无限可能、全球领先、极致体验”替代真实信息。

主要行动与当前准备程度匹配：资料不够时先帮助比较和理解，能够决策时直接进入购买、预约、试用或询盘。次要行动承接尚未准备好的访客，不给每个模块都机械配相同按钮。

交接前删除无法解释作用的模块，补齐最影响判断的内容；不要把文档篇幅当作策划完成度。
