# 两个 Skill 与已有建站的配合

当前执行者先识别范围并读取已有项目。完整新建/整体改版：website-plan-design → 当前建站 Skill 的正式工程与关键路径样板 → website-quality-review → 定向修订 → 扩展与必要业务检查 → 原部署流程 → 当前公网复验。局部修改直接由建站处理，按影响范围用验收 Skill；不强制进入完整策划。

计划可以只从产品名开始。研究确认的行业知识与对当前买家的假设分开，实际企业事实不编造。一般设计自主决定，只有无法继续的关键缺项提问。样板范围按产品和风险选，不固定三页、不固定某一行业路径。

资源检索、图像制作、浏览器和业务工具按缺口使用；不要求每次全部调用。只引入选中组件与当前需要的依赖。以项目现有文件作为交接，避免工具各自生成一套设计。

验收问题按根因返回：内容顺序/设计方向→策划，素材与裁切计划→素材准备，布局/交互/接口/性能→建站。修复后只重验影响路径，保留未受影响的有效结果。时间紧也不能把未执行改成通过。

本协议是执行者使用的工作方法，不是后台任务队列或自动调度程序。安装多个 Skill 不会自行启动其他任务。默认可由同一执行者依次使用；不预设多代理、不虚构独立评审。后续真正自动化需有明确调用器、当前项目状态、失败退出和恢复机制，另行验证。
