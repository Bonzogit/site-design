# 与建站和验收的工作流

| 阶段 | 主要输入 | 实际输出与下一步 |
|---|---|---|
| 策划设计 | 当前产品/业务需求、已有资料、可访问参考与资源 | 页面与模块蓝图、内容草稿、视觉规格、资产要求、操作预期→建站 |
| 建站样板 | 同一方案与实际业务接口 | 能走完关键路径、覆盖主要设计风险的页面和状态→验收 |
| 样板验收 | 方案预期、当前实现与版本 | 实际画面/操作结果、可修复问题→对应环节 |
| 修正与扩展 | 问题根因与有效样板决定 | 定向修复并复验，然后扩展其余页面与必要业务功能 |
| 交付检查 | 当前完成范围、部署要求、已执行结果 | 按原建站流程交付；要求部署时确认实际公网版本和核心路径 |

用户只要方案时停在方案交付；局部样式或功能修改直接由建站处理，再按影响范围验收，不强迫从整站策划重来。用户指定的平台、部署目标与保留内容优先。

定位、页面职责、顺序或文案逻辑不成立→回策划；图片与真实资料缺失→回素材准备；布局、状态、接口、数据或性能错误→回建站。修复时保留已确认的方向，只重查受影响内容。方案因实际限制改变时同步回写，不能让验收继续对着旧目标判断。

资源检索、图片生成、浏览器、仓库与业务工具按缺口调用，不要求每次全部使用。没有本地库或某个检索平台仍可通过实际可访问来源完成工作；只有阻断目标的依赖才需要解决后继续。

本流程由当前执行者实际执行，不是安装后自动运行的调度器。同一执行者可顺序使用三个 Skill，记录真实调用与交接；不虚构并行代理、独立评审和工具完成状态。
