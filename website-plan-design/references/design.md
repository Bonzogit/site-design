# 从内容得到具体设计

## 参考与主方向

先写出本次需要参考解决的问题，再查页面。记录其内容类型、构图、尺寸、状态以及准备借鉴的具体手法，避免只记网站名称和“高级感”。一份参考可负责整体视觉，其他参考只补明确缺口；不能平均混合几套互相矛盾的字体、圆角、密度和交互。

对候选主方向比较：是否帮助主要任务、是否适合实际图片、能否容纳真实内容、手机是否成立、现有技术能否实现。形成一个明确推荐并说明放弃另一方向的原因，不把未选择的三套方案丢给用户做设计师。用户要求精确还原时以目标为准。

## 需要落定的决定

| 维度 | 如何决定并交接 |
|---|---|
| 首屏与版心 | 按产品识别与主要任务确定图文比例、可见内容和操作位置；写实际最大宽度、边距与内容密度。不要默认每站大标题加右侧浮图 |
| 字体与文字层次 | 选可用且授权明确的字体，给标题/正文/标签的字号、字重、行高和行长；以实际长标题测试。中文、数字、英文和参数应同样可读，不靠标题字数删减遮掩布局问题 |
| 色彩 | 用语义指定背景、表面、正文、弱文字、边界、主操作与错误颜色；品牌色用于识别与行动，避免所有区域都高饱和竞争。提供本次具体值并核对可读性 |
| 栅格与节奏 | 依据比较关系和内容长度决定列数、对齐、间距及模块间节奏；相关内容成组，重要内容有尺度差异。不是所有段落都包成等宽圆角卡片 |
| 图片 | 指定每张图解释什么、主体与视线位置、比例、背景、留白、裁切焦点、桌面/手机版本、占位与失败回退；图片风格要能一起使用，不靠滤镜掩盖不相关素材 |
| 组件 | 按任务选列表、表格、画廊、步骤、筛选、标签页等；解释为何优于更简单的表达。参数比较优先保证同一维度对齐，不能只因某个组件好看而采用 |
| 状态 | 只列当前存在的操作与状态：默认、悬停、焦点、选中、加载、空、成功、错误、禁用。明确数据变化、按钮反馈与返回后的状态，不画假功能 |
| 响应 | 以内容挤压和操作需要决定断点；写清内容重排、表格浏览、媒体换图、菜单与触摸行为。图片与文字不能只按桌面等比缩小 |

这些决定保存到一份当前规格，避免文档、CSS 和组件参数各自给出不同值。确定值应服务产品，禁止把参考中某组数值升级为全行业默认。

## 素材制作与资源选型

素材清单至少有用途、来源或制作方式、尺寸/比例、裁切与授权状态。需要生成图片时提供主体、角度、环境、光线、材质、背景留白、统一风格和排除内容；没有生成工具则给制作要求并选择现有可用表达，不假装资产已生成。标志、工厂、证书、客户与产品实拍不得由概念素材冒充。

外部组件采用前确认独立入口、依赖、许可、数据输入、事件、销毁方式和无脚本回退。优先适配当前技术栈，不为一段动画导入另一套应用框架。资源目录是候选来源，不是每次必须调用的完整流水线。

## 动效必须有用途

先说明动效帮助理解结构、比较差异、反馈操作还是形成阅读节奏，再决定是否采用。交接触发条件、运动对象、起止状态、持续/停止、离屏与后台处理、触摸行为和减少动态回退；静止时同样应能完成任务。

不要默认每站都做浮动产品、整页滚动吸附、固定光标或重复淡入。保留用户明确喜欢的效果；运动尽量发生在媒体内部，链接与操作区稳定。无法实际观察参考动画时保留未验证，不能把读源码写成已体验。

## 样板验证什么

从当前方案中选风险最高的组合：最长标题与导航、最复杂的内容比较、最关键图片裁切或主要操作链。对样板写下可观察预期，例如“选中某项后对比信息与请求上下文一致”，而不是“看起来更高级”。这是给验收的目标，不提前填写通过结果。
