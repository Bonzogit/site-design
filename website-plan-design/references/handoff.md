# 策划交接

采用现有工程与 unified-site-builder 的项目文档，保持一份当前设计依据，不要求提前穷尽每个像素。

| 项目文件 | 唯一职责 |
|---|---|
| docs/SITE-BRIEF.md | 产品、访客任务、已知事实/假设/缺项、页面职责、关键路径、样板范围 |
| docs/DESIGN.md | 主方向、模块顺序与理由、素材需求、交互及手机表达；解释采用与拒绝 |
| docs/design-spec.json | 本项目确定的字体层次、颜色语义、宽度、间距、图片裁切与组件状态参数 |
| docs/design-record.json | 沿用建站当前 schema：designQuestions、references、decisions、journeys 与按版本核对结果 |
| docs/MODULES.md | 内容字段→后台位置→现有接口→实现文件→交互状态，登记所选组件 ID/版本/依赖与适配 |

已有工程可以使用等价文件，记录对应关系，不复制两套互相冲突的数值。原始引用、观察、推导、改编、继承和原创补充区分。没有外部参考的原创决定写产品依据，不补造来源。

每个主要模块回答：访客问题、内容与事实来源、出现位置/顺序理由、表现形式、素材要求、交互与手机行为、实际实现位置、怎样验收。只有方向明确且依赖可满足的模块进入样板；缺失事实不写假值，阻断操作的缺项需解决或明确缩小样板范围。

主题使用实际版本 createRenderer/context 接口；公开主题不接收私有询盘、账号、密钥或整个数据库。保留公开内容编辑、语言切换、异步补译状态与重试。原有网站不因新方案被重置。

交接结束报告“已足以开始样板”的依据及未决项。研究完成不代表页面验收通过；实现后的视觉与操作记录由实际检查补入。

交接前执行兼容性检查，记录建站版本、接口版本和实际项目版本。字段类型与证据路径以建站 `scripts/design_check.py` 的当前实现为准，由兼容检查调用它，不在本包复制 schema。详见[兼容性检查](compatibility.md)。
