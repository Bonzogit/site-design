# 交接给建站执行

涉及媒体、菜单与动效时，将[历史体验问题的预防决定](experience-prevention.md)写进当前模块：素材用途与复用、前后角度、裁切外框、首图/隐藏资源优先级、切图就绪与失败回退、命中区、偏好及静态布局。已有工程交接实际DOM和组件状态核对点；检查预期按当前版本与影响范围制定，不复制旧测试数字或继承通过结论。

交接的核心是明确决定与实际输入，不要求每个网站新建同样多的文件。仅咨询时直接给方案；进入实施时保存到工程已有的等价文档，说明对应位置，避免另建互相冲突的一套。

| 交接内容 | 建站执行者应能直接使用 |
|---|---|
| 网站任务 | 主要访客、入口、需要完成的判断或操作、主要行动、事实/假设/缺项 |
| 页面与模块蓝图 | 页面职责、导航和路径；模块顺序、内容草稿、数据来源、布局、操作、手机与验收预期 |
| 视觉规格 | 本次选定的方向与参考、字体、颜色、尺寸、间距、裁切和组件状态，数值只有一份当前来源 |
| 素材与组件 | 实际资产或待制作要求、采用来源与授权状态、独立入口、版本、依赖、生命周期与替代方案 |
| 内容与业务接线 | 可编辑字段→后台位置→读写接口→呈现位置；前端状态与持久数据的边界，关键成功/失败结果 |
| 实施顺序 | 能验证主要风险的最小完整样板、需先解决的依赖、暂缓内容与扩展条件 |

若已有建站能力不能实现某个设计，先判断能否在保留任务效果的前提下调整交互；涉及内容模型、交易或数据持久化时由建站明确扩展与检查，不能用演示数据伪造接通。缺失资料影响的模块单独标记，其余可行内容继续。

使用 unified-site-builder 时可对应 docs/SITE-BRIEF.md、docs/DESIGN.md、docs/design-spec.json、docs/MODULES.md 与 docs/design-record.json；字段类型以其当前检查器为准，详见[适配规则](compatibility.md)。这是该建站器的映射，不是通用 Skill 强制所有工具使用的目录结构。

研究、截图采集、画面观察与真实操作分别记录。交接阶段的验收预期保持待检查；实现后才补当前版本的实际结果。没有独立评审者时如实记录同一执行者，不能把 Skill 名称当成另一位代理。
